# Contract requests (frontend → packio-api)

Endpoints or fields the frontend needs that are not yet in `contract/openapi.json`. Each entry is mirrored by an MSW mock marked `// CONTRACT-REQUEST <id>`; remove both when the contract ships.

From F2 on, every request is also **code**: a zod definition in `src/lib/api/requests/` types the call site, validates the mock's responses, and is rendered by `pnpm gen:api` into [`contract-requests.openapi.json`](contract-requests.openapi.json) — an OpenAPI 3.1 document the backend can diff against what it builds. `registry.test.ts` fails as soon as one of them appears in `contract/openapi.json`, which is the signal to delete it here and there.

**Status column (U1 U-F0.1, 2026-09-29).** packio-api triaged every request in [`docs/contract-requests-triage.md`](../../packio-api/docs/contract-requests-triage.md) (its repo; against the tagged contract `v0.2.0`). `pnpm gen:triage` imports that into `src/lib/api/requests/triage.ts` and writes the verdict at the start of each Status cell; the note after ` · web:` is ours and survives a re-run. The verdicts: **Published as `<operationId>`** — shipped as asked; **Published differently (see mapping)** — the operation exists in another shape, and the screen applies the triage's per-field mapping when it migrates (U-F0.2–0.4), while packio-api adds the listed additive gaps in its group; **Open — packio-api U-B0.N** — built in that group; **Mixed** — per operation; **Rejected (reason)**; **Open — awaiting packio-api triage** — written after the triage. `contract-requests.openapi.json` now carries only the operations packio-api still has to build. `registry.test.ts` holds the cells, the registry, the triage and the contract to each other.

|---|---|---|

| OTP attempt limit | — | **not in the contract**; see `otp.attempts-remaining` above |
